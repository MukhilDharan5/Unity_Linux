# Implementation and validation matrix

Status applies to the full Linux–Android product, not merely a compiled handler. **Working** below means validated using real Linux D-Bus/TLS processes and a test peer. **Untested** means source exists and builds, but the corresponding Android permission/hardware behavior has not been exercised on a phone. **Partial** identifies a narrower implemented behavior. **Unsupported** means the current build explicitly rejects the operation. No physical Android device was available on 12 October 2026.

| # | Requirement | Current status | Implemented path / remaining gap |
| --- | --- | --- | --- |
| 1 | Device discovery and pairing | Partial; LAN pairing working with test peer | Explicit UDP discovery window, manual Android LAN address and verified TLS fingerprint, phone request, local approval, persistent credential. Android broadcast discovery UI and BLE discovery absent. |
| 2 | Automatic connection/reconnection | Partial; daemon restart/trust tested | Android exponential backoff/jitter, heartbeat and bounded sessions, trusted reconnect, replacement sessions. Physical suspend/resume, Android process restoration and OEM behavior untested. |

| 5 | Bluetooth and Wi-Fi/LAN | Partial; LAN working with test peer | Authenticated encrypted LAN and bulk transfer; interchangeable transport contract and selector; BlueZ inspection. BLE/GATT data channel, Classic profiles, Wi-Fi Direct and network capability negotiation are unavailable. |

All 21 requirements remain represented in independent Linux modules and the Android registry. Unavailable features remain visible in capability/settings documentation but do not appear as working controls. An Android permission grant is not sufficient evidence of hardware functionality; real-device checks are required before changing an untested row to working.

Foundation validation additionally covers two clients, read/control grants, blocked self-approval, operation ownership, path/scheme/numeric rejection, private credential permissions, wrong credentials, revocation, no stale live state after disconnect, and GUI uninstall independence. This project has no production interoperability with KDE Connect or Phone Link; it uses Unity protocol v1.
