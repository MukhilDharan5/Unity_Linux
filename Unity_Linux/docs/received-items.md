# Received file, link and text notifications

Update the Linux installation and install companion **0.1.9** over the existing debug APK to retain pairing. Every successfully received file, shared web link and shared text creates a native notification on its destination device, over either Bluetooth or Wi-Fi / LAN. This includes photos and remote-folder downloads sent through the file-transfer feature.

On Linux, click the notification or its **Open** action to open the original file in its default application or the link in a browser. Shared text opens in the default text editor as a private UTF-8 file. The daemon owns these actions, so the GTK window can be closed. The Files page also opens the received file directly.

On Android, tap the notification or its **Open file / Open link / Open text** action. Files open through their saved Downloads/Unity content URI with a read grant and a MIME type. Unknown file types offer an app chooser. Shared text opens a selectable text view; **Copy text** copies that notification's original text. Each notification holds its own immutable target, so later receipts and disconnections do not change older alerts. No received item opens before the user clicks.

Allow notifications on the phone using **Features → Notifications → Received file, link and text alerts**. This also opens settings for the separate received-items notification channel. OS notification permissions, muted channels, Do Not Disturb and desktop notification settings control whether a popup is shown. Notification-listener access, used for mirroring other phone apps, is separate from these receipt alerts. Disabling popups does not prevent a verified file from being saved or a link/text from appearing in Sharing.

Linux uses the desktop notification service and the OpenURI portal, with a `gio open` fallback where the portal is unavailable. Notification actions are retained for up to 128 active items until dismissed or the notification server/daemon restarts. Text files created by opening an alert remain in Unity's private received directory. Android Downloads survive app/service restarts; opening a file requires that it still exists and that an installed app supports its format. Android lock-screen alerts use private visibility.

Notifications appear after file size and SHA-256 verification and successful publication. Aborted or failed transfers, transfer chunks, battery updates, heartbeats and other background state do not produce receipt alerts. Feature permissions still gate received content. Android excludes Unity's own notifications from notification mirroring, preventing receipt-alert loops.

`tests/receipt_integration.py` exercises real daemon/TLS receipt delivery, notification signals and portal file descriptors on an isolated session bus. It checks exact old targets, offline clicks, activation tokens, forged-signal rejection, text escaping/private files, failed-transfer silence, disabled features, unavailable services and service restart. Android receipt tests cover immutable original targets, native viewer intents, exact MediaStore URIs, read-only grants, MIME fallback, text copying and rejected URLs. Phone permission/OEM behavior still requires a physical-device check.

Platform references: [Desktop Notifications Specification](https://specifications.freedesktop.org/notification/latest-single/), [OpenURI portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.OpenURI.html), and [Android notification navigation](https://developer.android.com/develop/ui/views/notifications/navigation).
