# Tests and evidence

Run `source scripts/env.sh` and `scripts/test.sh` from a normal development environment. Network is needed only when dependencies are not cached. In a restricted sandbox, actual D-Bus, TCP, desktop rendering, Gradle lock sockets and ADB inspection require permission to access local sockets.

- Rust unit tests validate protocol identity/version bounds, cross-language hello fixture, device/session-bound HMAC and an independently computed fixed vector, framing limits and interrupted header/payload resumption, transfer integrity/path validation, bulk transport selection, bounded backoff, all 23 feature descriptors, and rejection of unsupported actions.
- `tests/integration.py`, under `dbus-run-session`, starts the actual daemon and the actual CLI, establishes TLS 1.3 over loopback, verifies the certificate pin, pairs a test peer through an explicit CLI approval, and tests authorization, two client connections, live events, bounded photo preview results and private operation access, media artwork metadata, selected SMS conversation requests, streamed file bytes in both directions, persistence, restart, wrong credentials, and revocation. The peer is strictly a test fixture, never a production UI data source.
- `tests/audio_integration.py`, under `dbus-run-session`, tests actual daemon/CLI D-Bus and a separate pinned TLS PCM stream using isolated fake `pactl`/`parec` executables. It verifies PCM integrity, token scope/replay rejection, cancellation, startup failure, output restoration, feature disable, replacement sessions, revocation and crash recovery without changing desktop audio. Physical phone latency remains unmeasured.
- `tests/architecture.py` checks the daemon dependency graph, frontend API-only communication, independent service, staged installation, and frontend removal without changing daemon binaries/service/CLI.
- `tests/launcher.py`, under `dbus-run-session`, installs the actual binaries into a temporary prefix and substitutes an explicit test-only D-Bus client for the fixed GTK script. It verifies automatic approval of the launched child, refusal of an unrelated client with the same label, scope expansion, revocation surviving unrelated signals, reapproval after daemon restart, a fresh grant after reopening, and continued daemon operation after closing the client. No fixture path is accepted by the production launcher.
- The separate [Android project](../../Unity_Android/README.md) runs 69 protocol/image/audio/screen/lock/file/battery/TLS/connection/receipt and native-widget Robolectric tests. Battery tests cover sensor units/signs, smoothed runtime, Android charging estimates, missing/invalid sensors, measured trends, history resets, periodic sampling and disconnect cleanup. File tests exercise verified Downloads publication, empty files, Unicode/unknown extensions, bad hashes, write-failure cleanup and exact bytes from a one-shot document provider. Receipt tests cover distinct immutable notification targets, browser opens, file MIME/read-only grants, original text copy actions, viewer insets/dark appearance and notification settings after denied permission. See its [build and validation guide](../../Unity_Android/docs/build.md) and [UI documentation](../../Unity_Android/docs/ui.md). These checks do not validate physical phone permissions or transport behavior.
- `tests/gtk_smoke.py` renders the actual nine-page adaptive GTK client with explicitly isolated test fixtures in a separate application. It checks authorization gating before private snapshots, the friendly access prompt, control disabling on revocation, seventeen wide/narrow/light/dark layouts including Calls with separate output/microphone selectors, waiting and mute state, selected files and battery watts/runtime, charging and missing-sensor states, older companion notices, artwork/gallery rendering, font-scaled navigation breakpoints, and clearing private data on disconnect. Run with `GSETTINGS_BACKEND=memory GSK_RENDERER=cairo`. Captures are `/tmp/unity-refined-*.png`. The GUI has no production demo device or seeded fake phone state.
- `dbus-run-session -- python3 tests/file_transfer_ui.py`, with a GTK display available, exercises actual Gdk.FileList drop signals on all nine pages and another Unity window, multiple files and duplicate drops, symlink resolution, invalid/remote/oversized files, the public Transfer1.SendFile API, acknowledgements, retry selection, disconnects and disabled features. A temporary Broadway display can run this behavioral check without showing windows on the desktop.

The checked-in feature matrix distinguishes Linux protocol tests from Android hardware testing. Automated feature tests use an isolated TLS test peer. A paired phone was observed connected via LAN, but notification listener behavior, real SMS/carrier outcomes, SAF/MediaStore grants, MediaSession app behavior, DND/OEM policy, IME focus, accessibility gestures, battery reporting and long-term reconnect have not been validated end to end on Android hardware. Closing the GUI and removing its files are covered independently from those hardware limitations.

The installed native launcher and real GTK client were checked on Fedora with a paired SM-M356B: opening the app grants its fresh connection without a manual authorize command; the running client regains access after a daemon restart; quitting through the normal application action releases its registration; reopening receives a new grant while the daemon stays running. GTK exposes the normal quit action through Ctrl+Q and handles session-manager SIGTERM through its main loop.

Before distribution, test at least two physical Android versions, narrow and desktop GTK windows, suspend/resume, Bluetooth and Wi-Fi toggles, permission revocation, Android service termination, simultaneous devices, interrupted file transfers, malformed frames, a full transfer disk, stale document tokens, and changed TLS pins. Run device tests with carrier-aware consent before sending SMS. Do not declare a feature working merely because it compiles.

Known product gaps are in `features.md`: BLE transport, physical HFP/carrier call validation, direct MMS/RCS, desktop automatic clipboard integration, full photo-library pagination, and negotiated internet sharing. Phone notifications/SMS and received files, links and text have native desktop alerts. The operation history is capped and in memory; metadata/trust persists but phone contents and completed operations are cleared across daemon restarts.

The paired phone was observed connected over LAN during refinement, but no ADB device was attached for the latest APK update. Its MediaStore thumbnail, artwork, and SMS observer behavior remain hardware-untested. [Build the updated Android debug APK](../../Unity_Android/docs/build.md) and install it over the previous debug APK to retain pairing and settings, then check photo access and media permissions.

On 13 October 2026 a generated 33-byte file was sent over the installed daemon’s authenticated connection to the paired SM-M356B. The phone acknowledged the exact filename/size and the operation reached completed/100%. This verified receipt in the existing private storage implementation; the new 0.1.5 Downloads publication still requires installing the updated APK and a physical-device check. No ADB device was attached.

`tests/screen_integration.py` checks both screen stream directions and lock dispatch directions on actual D-Bus/TLS, plus authorization, token replay, oversized frames, permission denial, cancellation, feature toggles, stalled receivers, replacement and revocation. Isolated capture and lock fixtures prevent changes to the real desktop. `tests/screen_capture_test.py` exercises the actual portal helper’s calls and FD passing, with real GStreamer scaling/JPEG output from a test video source and permission-denial/session-close coverage. The suite also covers scoped remote input, read-only/stale-session rejection, and simulated brightness restoration on stop/disconnect/replacement/revocation. `tests/display_guard_test.py` checks independent parent-death/heartbeat recovery, exclusive panel ownership, saved brightness, local brightness changes, and journal recovery against a fake panel. The guard also tests panel power-off without dimming, missing virtual-output rejection, and journal recovery after the temporary output disappears. On 14 October 2026 real KDE capture was checked without a laptop dialog, with the actual laptop panel disabled, continued JPEG frames and remote pointer delivery, and automatic panel restoration/virtual-output removal. No screen pixels were saved. Physical phone capture/locking and end-to-end phone gestures remain untested.

`tests/bluetooth_integration.py` runs the complete integration, audio and screen lifecycle suites over descriptors supplied through a private BlueZ ProfileManager/Profile fixture. It checks service UUID/options, callback sender rejection, pairing/proofs, files in both directions, profile-role/token rejection, transport reporting, explicit profile disconnection, owner restart recovery, PCM/JPEG bytes and cancellation/revocation. No real Bluetooth adapter is configured by tests. `BluetoothTlsTest` exercises real TLS 1.3 over fragmented byte streams, duplex 256 KiB file bytes, wrong certificate pins and truncated records. Physical Bluetooth remains untested.

`tests/dual_transport_integration.py` opens real simultaneous authenticated LAN and BlueZ descriptor/TLS connections for one phone. It verifies routing, state retention, an incoming LAN transfer spanning BT connection, both heartbeats, per-link replacement/disconnection, operation ownership, both fallback directions, policy broadcasts, disconnect/revocation of both links, and continued LAN audio and screen sharing across BT join/loss. Android coordinator tests exercise actual framed read/write loops and independent reconnects with isolated stream peers, originating-link replies, and transfer affinity after loss/reconnect. Physical dual-radio behavior remains hardware-untested.

`tests/receipt_integration.py` uses actual D-Bus/TLS daemon receipts with isolated notification and OpenURI portal services. It checks exact original file descriptors/links, offline and older clicks, activation token ordering, forged action rejection, escaped text and mode 0600, silence for unfinished/failed transfers and telemetry, disabled features, unavailable notification services and server restart. No test receipts are shown on the real desktop. See [received-item notifications](received-items.md).

`tests/telephony_integration.py` covers actual D-Bus/TLS telephony commands, native notification actions, contacts, DTMF, SMS report retention and two-way HFP module cleanup with an isolated sound server. Android telephony tests cover opt-in/default-role permissions, local dialer lifecycle, safe numbers, call state gates, multipart duplicates and carrier failures. Physical carrier calls and HFP remain untested; see [telephony](telephony.md).

`tests/hfp_integration.py` tests live-call controls against a private-bus oFono HFP fixture; no physical call or Android privileged command is issued. Android tests verify ordinary permission gating without a default Phone role and verify that the optional Phone integration binds through an OS-protected InCallService without MANAGE_ONGOING_CALLS or MODIFY_PHONE_STATE.

`tests/call_popup_ui.py` runs on an isolated Wayland desktop and checks shared popup/page timers, hold/end/answer/decline/mute, native speakerphone command forwarding, computer output synchronization, unavailable HFP routes, popup dismissal/reopening and authorization cleanup. `tests/launcher.py` also checks the call-popup argument and its verified child grant. Android PhoneCallTest checks role opt-in, real Telecom route mapping, stable call IDs, unavailable/stale requests, local call UI while disconnected and remote emergency/role gates.

`tests/call_popup_integration.py` needs an isolated KDE virtual desktop. It checks the actual GTK command-line popup path with the main app closed, automatic PID-verified authorization, compositor keepAbove, and call-end closure. HFP tests also restart their private telephony service with unpowered modems lacking Serial and require saved-phone recovery without powering the other phone.
