# Device volume in both apps

Install companion **0.1.16** and the current Linux build. Enable Android **Features → Media → Media and sound controls**. Linux **Media → Device volume** and Android **Overview → Media players → Device volume** offer independent laptop-output and phone-media sliders (0–100%) and mute/unmute buttons. They work without an active music player. Android notification-listener access is only needed for phone player discovery, not for these volume controls.

The laptop slider controls the current default PipeWire-Pulse/PulseAudio output, including a selected Bluetooth output or Unity's audio-routing sink. Its output name and percentage are shown. Changing the default output updates the control; an old pending gesture cannot silently control a new output. Phone volume uses Android's music stream and its actual minimum/maximum steps. It does not change ringer, notification, voice-call or microphone levels. Android fixed-volume policies and sound-server unavailability disable the affected controls with an explanation. Existing laptop levels above 100% show `>100%`; Unity's slider writes are limited to 100%.

Volume keys and system-settings changes are polled into the UI. Received state is display-only. Programmatic slider updates issue no setters, slider gestures are debounced on GTK, Android sends on gesture release, and explicit controls use absolute values. Bounded request histories ignore identical replays and reject changed replays, so a duplicate cannot undo a subsequent volume-key change. The daemon rechecks the paired connection and feature permission before dispatch; GTK cancels pending gestures after revocation, device changes or output switches. Turning off Media or Device volume in Linux, or Media and sound controls on Android, stops sharing/control. Reconnection clears old state before accepting a new initial snapshot.

The `sound` capability adds phone-native events (`origin:"phone"`) and laptop-native events (`origin:"desktop"`). Linux stores them separately in Device1 state as `sound` and `desktop_sound`. Commands are `volume {source,volume}`, `mute {source,muted}`, and `refresh {source}`. Laptop volume/mute commands also require the current opaque `output` ID. Phone desktop Requests can only target `source:"desktop"`; local Device1.Execute routes `source:"phone"` to Android and `source:"desktop"` to the laptop. Laptop responses include the refreshed state for prompt slider feedback. Echoed laptop events are discarded rather than reused as phone state.

`tests/sound_integration.py` tests the actual daemon and TLS/D-Bus using an isolated pactl implementation: both targets, external changes, replay guards, output switches, feature revocation, validation and server recovery. `tests/media_ui.py` checks real GTK controls, update silence, gesture debounce/cancellation and the existing media controls on a virtual desktop. Android `SoundTest` uses real widgets plus isolated AudioManager state to check music-only changes, percentages, absolute mute, fixed-volume policies, source separation, both transports, replay protection and stale gestures. Captures include `/tmp/unity-media-both-*.png` and Android `app/build/reports/unity-preview/sound-both-light.png`. Native laptop readback was verified against the real sound server; physical Android volume behavior remains a device check after installation.

Platform references: [Android AudioManager](https://developer.android.com/reference/android/media/AudioManager), [PulseAudio volume UI guidance](https://www.freedesktop.org/wiki/Software/PulseAudio/Documentation/Developer/Clients/WritingVolumeControlUIs/).
