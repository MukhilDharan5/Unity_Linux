# Android companion interface

Companion **0.1.31** compares every available media artwork source before selecting a cover, keeping the largest source and preserving better cached art during failures. Track-bound seeks from native desktop media controls are rejected if the phone has changed tracks. The corresponding Linux update adds per-session desktop MPRIS players and original-file gallery dragging; see [media validation](../../Unity_Linux/docs/media-sync.md) and [gallery behavior](../../Unity_Linux/docs/gallery.md).

Companion **0.1.30** remembers public/private Wi-Fi choices using a device-local hash of the connected profile, with Android's foreground Location permission for reading the Wi-Fi name. Reconnects, roaming and service restarts retain choices. Received file notifications launch supported viewers directly with read-only grants; fallback receipt activities wait until resumed and handle repeated taps without losing the original item. See [network privacy](../../Unity_Linux/docs/public-wifi.md) and [received items](../../Unity_Linux/docs/received-items.md).

Companion **0.1.29** routes fingerprint notifications directly to the request review activity using an immutable, request-specific PendingIntent. Tapping keeps the notification available until approval, decline, cancellation or expiry. Activity restoration and repeated notification taps retain the correct request; an old notification cannot select a newer request. Expired/unavailable requests and biometric errors show an explanation on the review page. While a request is pending, Features exposes **Review fingerprint request** as an in-app fallback. The legacy MainActivity route is consumed once, including during saved-state restoration.

Companion **0.1.28** adds native Android MediaStyle notifications and remote MediaSessions for laptop playback, with title/artist/album, duration/position, cover art, supported play/pause/skip/seek actions and laptop volume. These feed Android system media controls while keeping laptop state separate from phone-native player discovery. Cover art now uses original image sources and up to 1024-pixel JPEGs throughout the media page and system session; see [media behavior and validation](../../Unity_Linux/docs/media-sync.md).

Companion 0.1.2 uses native Kotlin Android Views with an Adwaita-inspired style layer. It shares Unity Linux's blue accent, app icon, neutral backgrounds, rounded bordered cards, divided preference rows, typography hierarchy, and restrained spacing. Android does not embed GTK or require a GNOME runtime. The production APK has no new UI-library dependencies; Robolectric is a test-only dependency.

Companion **0.1.27** applies that shared style to the dialer, incoming/active calls, fingerprint credential setup and request review, media selector and sliders, screen-viewer controls, and all app-owned dialogs. Dialing includes a styled keypad, cursor-aware editing, delete/hold-to-clear and grouped history/permission states. Calls show a caller card, live duration, an optional keypad, microphone switch and selected audio route. Approval uses grouped request details, a primary fingerprint action, password fallback and a confirmed destructive credential reset; ended requests disable approval immediately. Android continues to provide biometric, permission and document-picker dialogs.

`AdwaitaActivity` supplies secondary screens with the saved appearance, a back/header bar, centered content capped at 720 dp, and system/cutout/keyboard insets. `AdwaitaUi` supplies shared neutral, suggested, destructive and disabled buttons, icon buttons, keypads, sliders, selectors and rounded dialogs. Choice dialogs retain native single-selection and dismissal behavior, use a checkmark for the current choice, and stack action buttons when space or text size requires it. Existing credentials, opt-in permissions and call/authentication protocols are preserved.

`AdwaitaScreensTest` renders `phone-dialer-light`, `phone-incoming-dark`, `phone-call-dark`, `fingerprint-setup-light`, `fingerprint-review-dark`, `connection-dialog-dark`, and `fingerprint-reset-dialog-light` under `app/build/reports/unity-preview/`, plus narrow-screen large-text captures. It exercises draft recreation, cursor edits, offline calls, live request cancellation, reset confirmation, appearance overrides and keyboard safe areas. Call and authentication details in these screenshots are test fixtures.

The navigation adapts to the available space:

- **Overview** shows actual connection state, the saved computer, connect/disconnect actions, and shortcuts.
- **Sharing** contains file sending, shared-folder selection, automatic clipboard status and Shizuku background-access setup, and URL sharing/opening.
- **Features** groups opt-in switches and Android permission/setup actions by notifications, messages/calls, files/photos, clipboard/links, media, remote control, and internet sharing. Remote locking and screen sharing have opt-in switches and native approval actions. Messages and calls now includes default-off Call management, ordinary phone/contact/history permissions and an optional in-app dial pad. Linux selects a paired Bluetooth HFP phone for live call control; the normal Phone app handles its call screen unless the user enables optional phone speakerphone controls and chooses Unity as the default Phone app. That setup explains the role change and enables Unity’s local call screen, which works offline too. Settings defaults to simultaneous Bluetooth + Wi-Fi / LAN connections, with single-transport options, a bonded-computer picker and Nearby devices permission flow.
- **Settings** contains computer address/port/verified TLS fingerprint, pairing removal, system/light/dark appearance, notification exclusions, and app information.

Phones use a bottom view switcher. Wide windows use a sidebar and a content width capped at 720 dp. At narrow widths or larger font settings, the bottom switcher uses icons with accessible names rather than truncated labels. Text uses sp, spacing uses dp, rows grow with wrapped text, interactive controls have at least 48 dp height, and section titles carry accessibility heading semantics. Native window insets keep content clear of system bars, cutouts, and the keyboard.

The interface observes process-local service state events and preference changes. It does not poll the phone or create transport connections. State invalidations are coalesced on the main loop; no exported status receiver exists. It registers observers only while visible, rechecks state on return, and disables sending controls when the transport or required capability is unavailable. The service owns transfers and connection lifetime; leaving the activity does not stop either. Incoming clipboard text is applied automatically by the service. Clipboard changes send automatically when Android permits reading; background sending uses authorized Shizuku access and keeps the current keyboard. Sharing → Background clipboard access opens setup/authorization and links to the Shizuku guide; status reflects reader startup, denial, loss and recovery. Clipboard starts enabled unless explicitly disabled.

Existing preference names, phone identity, Android Keystore credentials, and wire protocol v1 are preserved. Editing the TLS identity now requires confirmation before removing the previous pairing credential. Forgetting the computer also requires confirmation, stops the connection, and explains that the computer's saved trust must be revoked separately. Configuration changes preserve the current page and draft input; recreating the activity does not replay an Android share intent.

Native Android 15 Robolectric tests render the actual production widgets and exercise offline controls, consent, automatic clipboard changes, saved drafts, activity recreation, system/keyboard insets, live connection events, and independent service lifetime. PNG captures are generated under `app/build/reports/unity-preview/`. Validation on 2026-10-30: Preview 0.1.27 builds with 113 passing Android tests and zero lint errors. The secondary-screen checks include native light/dark rendering, large text, keyboard safe areas, offline calling and fingerprint-request lifecycle. These are automated checks; physical phone calls and hardware biometrics still require device validation.

Earlier validation on 2026-10-12: the debug APK built successfully, all 17 Android tests passed (10 UI tests and 7 protocol/image tests), and Android lint reported zero errors and six warnings. The UI tests also verify that an explicit dark appearance overrides a light system setting. Remaining lint warnings concern target SDK updates, the existing pinned TLS trust manager, backup rules, and intentional synchronous preference writes.

Build and test with the commands in [build.md](build.md). The updated debug APK can be installed over companion 0.1.1 using the same application ID and signing key, retaining pairing and settings. Android feature permissions, OEM background behavior, and real file/notification/media outcomes still require physical-device validation.

Design references: [GNOME UI styling guidance](https://developer.gnome.org/hig/guidelines/ui-styling.html) and [Android window-inset guidance](https://developer.android.com/develop/ui/views/layout/edge-to-edge).

Overview includes Lock computer. Sharing includes Share phone screen, View and control computer screen, Use phone with laptop display off, Stop screen sharing and current status. A dedicated image viewer fits the live computer capture to the screen; closing it stops sharing. Taps/dragging control the approved laptop monitor, two fingers scroll, and the keyboard icon toggles the selected Android keyboard. A display icon restores/blanks the laptop panel during sharing. Initial blanking waits for a decoded frame in the visible viewer; session end or connection loss restores brightness. Background capture requests post an action notification instead of launching an activity without user interaction.

Companion 0.1.9 includes Features → Notifications → Received file, link and text alerts for notification permission/channel settings. Receipt notifications open the original file or link directly. Text alerts open a selectable text view and provide a Copy text action, retaining the original text after later shares. Files without a supported viewer offer a chooser and remain in Downloads/Unity. These alerts are separate from notification mirroring permissions. See [received-item notifications](../../Unity_Linux/docs/received-items.md).

Companion 0.1.15 adds **Overview → Media players** and **Features → Media → Open media players**. The native MediaActivity selector lists laptop and phone apps, with track details, playback position, artwork when available and explicit controls. Incoming metadata and player selection never trigger playback. The two-device fixture is rendered at `app/build/reports/unity-preview/media-both-light.png`.

Companion 0.1.16 puts **Device volume** above the player chooser: independent laptop output and phone media sliders, percentages and mute/unmute. External changes update widgets without sending commands. Capture: `app/build/reports/unity-preview/sound-both-light.png`.
