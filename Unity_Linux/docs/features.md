# Implementation and validation matrix

Status applies to the full Linux–Android product, not merely a compiled handler. **Working** below means validated using real Linux D-Bus/TLS processes and a test peer. **Untested** means source exists and builds, but the corresponding Android permission/hardware behavior has not been exercised on a phone. **Partial** identifies a narrower implemented behavior. **Unsupported** means the current build explicitly rejects the operation. No physical Android device was available on 12 October 2026.

Android broadcast discovery UI and BLE discovery absent. |

All 23 features remain represented in independent Linux modules and the Android registry. Unavailable features remain visible in capability/settings documentation but do not appear as working controls. An Android permission grant is not sufficient evidence of hardware functionality; real-device checks are required before changing an untested row to working.

Foundation validation additionally covers two clients, read/control grants, blocked self-approval, operation ownership, path/scheme/numeric rejection, private credential permissions, wrong credentials, revocation, no stale live state after disconnect, and GUI uninstall independence. This project has no production interoperability with KDE Connect or Phone Link; it uses Unity protocol v1.
