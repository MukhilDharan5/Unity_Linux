# Laptop and phone media players

Update Linux and install companion **0.1.31**. On Android, enable **Features → Media → Media controls**. Notification-listener access is required for discovering native phone players. Laptop players use the desktop session's [MPRIS interface](https://specifications.freedesktop.org/mpris/latest/), with no additional Android notification permission.

While connected, Linux's **Media → Players** selector lists native laptop and phone sessions. Android's **Overview → Media players** and **Features → Media → Open media players** open the same two sources. Each entry identifies **Laptop** or **Phone** and its app. Selecting an entry preserves that selection across metadata and playback changes. Play/pause, previous/next and seeking operate on that exact player, subject to the app's supported actions. A player that closes or restarts cannot receive controls intended for its old session.

Both apps show track, artist, album, duration and position. Phone artwork is loaded independently from playback updates, using metadata bitmaps/URIs and media-notification covers when available. Missing artwork retries rather than remaining cached as empty. Laptop MPRIS cover URLs are fetched into bounded high-quality JPEG covers with size and time limits; missing covers retry without issuing playback commands. Apps that expose no artwork still use the placeholder. Laptop apps must expose MPRIS; phone apps must expose an active Android MediaSession. Audio plays on the originating device. The existing laptop-audio-on-phone option remains a separate routing control.

## Android system controls and high-quality covers

Companion **0.1.28** creates a remote Android MediaSession and MediaStyle notification for each playing laptop player. Now playing, Quick Settings, lock-screen controls and media keys use the player’s actual title, artist, album, duration, position, cover and supported actions. Paused players retain resume controls until that player closes, media is disabled or the connection ends. Play/pause, previous/next and seeking route to the exact laptop session; seeks also carry its current track ID. The native volume control adjusts laptop output when the paired computer exposes volume support. Metadata and external volume updates never send control gestures. Audio remains on its current device; this does not request phone audio focus or start an audio stream. Android/OEM-specific live tiles still require physical-device verification. See [Android’s media-control surfaces](https://developer.android.com/media/implement/surfaces/mobile).

Media artwork preserves up to **1024 × 1024** pixels, keeping the original aspect ratio, using JPEG quality 92–80 with a **192 KiB** cover budget. Companion **0.1.31** compares all distinct album-art, art and display-icon URIs, the largest embedded bitmap, 1024-pixel provider thumbnails and session-matched notification artwork. It keeps the largest available source rather than accepting a small first URI or letting a small bitmap block provider artwork. HTTPS sources allow bounded HTTPS-only redirects, with byte, pixel and time limits. Temporary failures cannot replace a better cached cover with a smaller image. Both app media screens and native system players use the full cover. An unavailable higher-resolution source cannot be reconstructed from a small thumbnail.

## Phone playback in desktop Now Playing

The Linux daemon exports each connected, enabled phone-native session as `org.mpris.MediaPlayer2.unityconnect.d_DEVICE.s_SESSION`. GNOME Now Playing, compatible desktop widgets and MPRIS clients see the actual title, artist, album, playback state, duration, position and cover even with the Unity window closed. Play/pause, previous/next, relative seeking and absolute seeking route to that exact phone session. Seeks carry its track identity so an old desktop gesture cannot seek a replacement track. Volume adjusts phone media volume when the phone exposes that capability; it does not change laptop output.

Supported controls reflect the phone app's actions. Playback speed, opening arbitrary media URLs and quitting the phone app are not exposed as controllable capabilities. Paused sessions remain available for resume; ended sessions, disconnects, revoked pairing and disabled media remove their desktop players. High-quality covers are served through private local JPEG files and removed when no exported player uses them. No local audio stream is created. The existing audio-routing controls remain separate.

The MPRIS service names and Unity DesktopEntry are excluded from laptop-native discovery, so exported phone media cannot bounce back to the phone as a laptop session. The native interface deliberately shares the opted-in phone media metadata with desktop media clients; private Unity D-Bus APIs still require their usual access grants. The implementation follows the [MPRIS Player interface](https://specifications.freedesktop.org/mpris/latest/Player_Interface.html).

Update Linux too. Peers negotiate `media_artwork`; high-quality covers then travel independently of the small metadata/timeline frame, preferably over LAN, once per track/content/transport. A SHA-256 content ID binds each cover to the player’s current artwork reference. Bounded caches tolerate the bulk image arriving before metadata on the other link, preserve full covers over timeline refreshes, and prevent an old cover being displayed on a different track. Older builds keep the 128-pixel inline preview and normal controls. Gallery photo/video previews retain their separate size limits.

## Loop and replay protections

- Phone-native metadata is sent as `media` with `origin:"phone"`; laptop-native snapshots use `desktop_media` with `origin:"desktop"`. The models stay separate. Laptop state is never republished as phone-native media. Android exposes explicitly remote MediaSessions for system controls and excludes Unity’s own package from native-phone discovery; phone state is exported only in Unity’s excluded remote MPRIS namespace.
- Discovery excludes Unity's own phone sessions and known Unity/KDE Connect/GSConnect MPRIS bridges. Linux drops returned laptop snapshots and foreign-origin phone events before caching or dispatching. Android ignores foreign-origin laptop snapshots.
- Rendering, selecting a player and receiving metadata issue no playback commands. Only explicit control gestures issue a command, which is sent directly to the originating player. Updates never call play/pause to synchronize playback states.
- Phone MediaSession tokens and laptop bus-owner identities determine session IDs. Commands use those IDs without silently falling back to another player. Desktop seeks also carry a track ID and reject a changed track. GTK cancels delayed seeks when selection changes.
- Replayed media command IDs are remembered in bounded histories. Linux remembers up to 256 recent requests for ten minutes; Android remembers up to 256 commands for the connection lifetime, including both simultaneous transports. Identical repeats do not execute next/previous twice. Changed replays are rejected. Ambiguous failures are not automatically retried.
- The existing paired-session, feature and permission checks apply in both directions. Disabled media or a disconnected phone stops sharing. Metadata is bounded to 16 players and a control frame; unchanged snapshots are suppressed. Artwork work uses bounded caches and worker queues.

## Timeline recovery

The desktop queries the live MPRIS Position property every second; it does not depend on a playback-state change. GTK advances the displayed clock between samples. A temporarily missing duration or cover is retained only for the same identified track, and a new track cannot inherit the old duration. Unknown-duration media shows an explicit progress indicator rather than an empty seek bar. Android publishes playback metadata immediately while artwork jobs run separately, preventing a slow image provider from freezing timeline updates. Neither polling nor the UI clock calls play/pause to obtain fresh state.

`tests/media_integration.py` checks late artwork recovery, preserved same-track duration and updated Position without transport controls. `tests/thumbnail_test.py` decodes real bounded cover data and rejects unsupported inputs. GTK media checks cover an advancing clock, missing duration, new-track reset and control silence. Android `MediaTest` checks running playback and a late cover without pause/resume. Artwork source details are defined by [MPRIS metadata](https://specifications.freedesktop.org/mpris/latest/Track_List_Interface.html); position behavior follows the [Player interface](https://specifications.freedesktop.org/mpris/latest/Player_Interface.html).

`tests/phone_media_integration.py` verifies actual desktop MPRIS discovery, per-session controls, seek units and track guards, phone volume, high-quality local cover files and PropertiesChanged signals, removal on session end/disconnect/opt-out, and exclusion from laptop-native discovery. Android `MediaTest` compares competing URI/bitmap resolutions and rejects stale-track seeks. GTK `gallery_ui.py` requests the actual drag provider’s URI stream and verifies asynchronous original-file delivery, Unicode escaping and denied access.
